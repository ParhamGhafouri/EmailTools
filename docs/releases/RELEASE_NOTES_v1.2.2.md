# Email Tools v1.2.2

Version 1.2.2 is a major reliability, indexing-isolation, search-capability, and lifecycle-hardening release. It eliminates persistent **`"Outlook is closing"` shutdown hangs (`Event ID 51`)** and slow cold-boot penalties, introduces **strict shared/secondary mailbox index isolation with automatic removal and permission-revocation cleanup**, adds **background document & `.msg` attachment full-text indexing (`attachment_fts`) with flicker-free search-bar match pills, a multi-attachment picker menu, Preview Pane match counts, Status file counts, and bulk search actions**, adds a **primary-mailbox-scoped Archive Dry-Run Preview (`Preview Eligible...`) with no-quota completion hardening**, upgrades **Task Tracker `"Waiting for Reply"` tracking, rule safety, and cross-store bilingual reply reconciliation**, and fixes **mixed-DPI scaling, Persian/Unicode search parity, auto-update recovery, and SQLite self-healing**.

### Highlights (Ordered by Priority)

1. **Instant Outlook Shutdown (`"Outlook is closing"` / Event ID 51), Sub-Second Warm Boot & Zero-Stall UI Responsiveness:**
   - **`PSTNullFreeOnClose` Removal & Fleet Self-Healing (`mspst.dll` / `EMSMDB.DLL` Event ID 51 Fix):** Replaced `SmartArchive.EnsurePstCompactionOnCloseConfigured()` (which previously wrote `PSTNullFreeOnClose = 1` under `HKCU\Software\Microsoft\Office\<ver>\Outlook\PST`, forcing `mspst.dll` to synchronously zero-fill free pages across every mounted `.pst` on exit and stalling `"Outlook is closing"` for minutes—even after uninstalling) with `SmartArchive.ClearPstNullFreeOnCloseIfSet()` in `DeferredInit`, `SmartArchive`, `EmailTools.iss`, `clear_outlook_resiliency.ps1`, and `uninstall_cleanup.ps1` across Office `16.0`, `15.0`, and `14.0`, cutting multi-PST shutdown to under `1 second` and automatically healing previously affected PCs on upgrade or uninstall.
   - **Zero-Wait Non-Blocking SQLite Shutdown:** Updated `BodyIndex.PrepareForProcessShutdown()` to cancel a dedicated `_shutdownCts`, call native `sqlite3_interrupt` across `_rcn` and active snapshot queries (`TryQuerySnapshotAllowed`, `TryQueryMetadataSnapshot`, `TryQueryMailMetadataSnapshot`), and acquire `_rcnLock` via zero-wait `Monitor.TryEnter(_rcnLock, 0)` (closing `_rcn` immediately when uncontended or queuing off-thread cleanup once interrupted readers unwind). Added fail-closed `IsStopRequested` short-circuits across all `BodyIndex` read helpers (`ReadConn()`) and a `BodyIndexService.OpenForSearch()` shutdown guard calling `PrepareForProcessShutdown()` instead of blocking on `_writer.Join`.
   - **Zero-Stall Live UI Responsiveness & `Event ID 59` Callback Guard:** Eliminated `Folders.FolderChange` unread-count full-sweep storms and duplicate folder re-walks, gated live indexing, folder reconciliation, quota refreshes, and Conversation History folder checks on active user input idle, deferred `NewMailEx` item opening off Outlook's event callback, coalesced `SelectionChange` Ribbon attachment refreshes via `BeginInvoke` and deferred `FolderSwitch`/`Activate`/`ViewSwitch` search-band layout to the settle timer (preventing `Event ID 59` 500ms callback spikes), skipped redundant Task Tracker COM reads on in-place `ItemChange`, eliminated per-row table-scan closure allocations, and added non-blocking indexed Ribbon attachment detection (`HasRealAttachmentForRibbon` / `TryHasIndexedRealAttachments`) so clicking messages with inline signatures never stalls Outlook's Reading Pane.
   - **Shared-RCW Unadvise Ordering & Multi-Store COM Cleanup:** Fixed Explorer, Inspector, `ParhamRibbon`, and `MessageListSearchBandManager` shutdown and single-window close paths to unhook shared COM event sinks *before* releasing only owned RCWs once via `Marshal.ReleaseComObject` (removing premature `FinalReleaseComObject` / double-release paths). Explicitly released `NameSpace`, `MAPIFolder`, `Outlook.Columns`/`Column`, `PropertyAccessor`, `Stores`/`Categories`, and item RCWs across `BodyIndexBuilder`, `MailSearchEngine`, `MailSearchPanel`, `SmartArchive` (`AddSkipFolder`), and `ConvHistoryRestore` (folder/delete/move/EWS/tree paths).
   - **Off-STA Signature Warmup, Multi-Window Lifecycle & Deferred Cold-JIT Boot:** Pre-warmed pinned worker Authenticode metadata asynchronously in `NameRepairWorkerLauncher.WarmPinnedSignatureCacheAsync()` off Outlook's STA shutdown thread, replaced single-Explorer tracking with multi-window Explorer and Inspector lifecycle tracking (`_hookedExplorers` / `CheckLastWindowClosing`), kept Task Tracker dormant when no active rules or open tasks exist, and deferred heavy Ribbon initialization outside the startup measurement window (`Event ID 45` sub-500ms warm boot, and well below Outlook's 1000ms threshold on cold start).

2. **Store Removal, Index Cleanup & Shared Mailbox Isolation:**
   - **Canonical Store Identity Keys:** Introduced `BodyIndex.ComputeStoreKey` so shared, delegated, and automapped Exchange mailboxes are isolated into distinct store keys even when cached inside the primary `.ost` file, while keeping local `.pst` paths normalized consistently.
   - **Immediate Detach, Purge & Live Search Scope Refresh:** Hooked `Stores.BeforeStoreRemove` in `BodyIndexService` and `TaskTrackerService` to detach folder event sinks immediately, purge removed stores from `bodyindex.db`, and notify Advanced Search (`RemoveUnmountedStoreFromScope`) so unmounted stores disappear from Search's Scope selector and in-memory cache immediately.
   - **Automatic Unmounted-Store, Mounted-Repair Filtering & Revocation Cleanup (`StepReconcile`, Startup Sweep & `ListStores`):** Updated `BeforeStoreRemove`, post-settle startup verification, background reconciliation (`StepReconcile`), and live store enumeration to purge all indexed rows across `mail_meta`, `body_fts`, `attachments`, `attachment_fts`, `folders`, `header_repair_pending`, and `empty_body_verified` for unmounted non-managed legacy `.pst` archives, user-dismounted `.pst` files, and unmounted or access-revoked non-default shared/secondary stores (`0x80070005` `MAPI_E_NO_ACCESS` immediately; `0x8004011D` `MAPI_E_FAILONEPROVIDER` after two consecutive failures while primary Exchange is online), including subfolder-level `0x80070005` revocation cleanup—while preserving unmounted/offline rows strictly for protected Managed Season `.pst` archives (`YYYY-SeasonN.pst`) that were not manually dismounted by the user, and filtering background repair/candidate queries (`SetMountedStores` / `BuildMountedStoreClause` / `IsStoreMountedForRepair`) strictly to mounted stores.
   - **Query-Time `AllowedStoreKeys` & Subfolder Wildcard Escaping:** Enforced `AllowedStoreKeys` across all SQLite search snapshot paths (`All Mailboxes` and multi-store scopes) so removed or revoked stores never return stale cached messages before cleanup completes, and escaped `\`, `%`, and `_` in `SearchScope.Subfolders` folder prefixes (`BuildSubfolderLikePattern` + `LIKE ... ESCAPE '\'`) so folders containing `%` or `_` never act as SQLite wildcards.

3. **Document & `.msg` Attachment Full-Text Indexing (`attachment_fts`), Preview Match Counts, Status Metrics & Bulk Actions:**
   - **Zero-Dependency Document, Embedded `.msg` & Persian/RTL PDF Extraction with Hardened Safety Bounds:** Added continuous bounded background extraction and SQLite FTS5 `trigram` substring indexing (`attachment_fts`) for attached Office and legacy Office documents (`.docx`, `.docm`, `.doc`, `.xlsx`, `.xlsm`, `.xls` including worksheet tab names, `.pptx`, `.pptm`, `.rtf`), **embedded Outlook `.msg` email attachments** (including MAPI compressed RTF, HTML bodies, recipient headers, and nested `.msg`/file attachments), PDFs (uncompressed, `FlateDecode`, and PDF 1.5+ `/ObjStm` compressed object streams up to 20 MB with per-font `/ToUnicode` CMap resolution, visual/logical Persian & Arabic RTL text reconstruction, Arabic Presentation Forms decomposition, and Persian/ASCII digit parity), and plain-text/markup/script/data files (`.txt`, `.csv`, `.log`, `.json`, `.xml`, `.html`, `.md`, `.sql`, `.yaml`, `.ps1`, `.sh`, `.py`, `.bat`, `.conf`, `.properties`) without external filters or UI stalls. Hardened `AttachmentTextExtractor` with `BoundedReadStream` / `ZipReadBudget` (`64 MB` cumulative decompressed ZIP cap and XML node caps), `64 MB` cumulative PDF payload cap, Form XObject `Do` recursion bounds, strict weak-ordering `NaN`/`Infinity`-safe Y/X line sorting, and a hard per-attachment extraction deadline.
   - **Non-Blocking `Phase: AttachmentRepair` Completion & Temp Hygiene:** Aligned idle gating with `UI_QUIET_MS = 1000`, ensured unconditional `finally` flushing of Stage 1 `batch` and Stage 2 `evalBatch` (avoiding premature empty marking on user-input interruption), recorded `content_indexed=1` up front in `UpsertAttachmentsBatchSync` for empty or non-extractable attachments while purging stale `attachment_fts` rows, filtered unmounted stores, bounded active cycles (`200` saved items / `500` COM attempts / `25s` cycle budget / `35s` drain cap) cleanly to `Phase.Done`, raised per-message extraction capacity to `16` attachments (`MAX_EXTRACTABLE_ATTACHMENTS_PER_MESSAGE = 16` and `MaxPreviewExtractableAttachments = 16`), and cleaned orphaned `%TEMP%\EmailTools_AttIdx` (>1h) and `%TEMP%\EmailTools_PvAtt` temp directories.
   - **Unified Body + Attachment Search, Search-Bar Match Pills, Multi-Attachment Picker, Preview Match Counts & Status File Count:** Search extracted document contents automatically from **both the `Body` field** (alongside email body text, including substring, multi-word, and exclusion queries) **and the `Attachment` field** (alongside attachment filenames and wildcards such as `*.pdf` or `*.xlsx`). When a query matches inside attachments, the active search box (`Body` and/or `Attachment`, as well as Task Tracker's `Search tasks` bar) displays a flicker-free, double-buffered, DPI-aware clickable inline match pill (`📎 N` for single-file hits, `📎 N ▾` when matched across multiple attached files with an Office-styled shell-icon dropdown menu to preview or open any matching attachment directly, `◀ x/y ▶` + `+N` when matched in both body and attachments, `N files` for filename/wildcard matches, and live `◀ x/y ▶` navigation when viewing `.msg`/`.txt` previews in-pane), while the Preview Pane computes non-overlapping deduplicated occurrence counts (`CountAttachmentQueryOccurrences` / `CountAttachmentCombinedQueryOccurrences`, capped at `9999` with `etns='1'` DOM isolation) across both the inline match banner and per-chip `#emailtools-att-chip-count-*` badges. The **Status** dialog's **Search Index & Engine** card also displays the live total indexed attachment file count (`CachedAttachmentFileCount`) alongside indexed messages and readable phase labels (`"Phase: Attachment indexing"` / `"Phase: Header verification"`).
   - **Bulk Search Actions & Thread Jump:** Added multi-select **Save Attachments...** and **Track as Task** actions in Advanced Search, plus the **`Ctrl+T`** shortcut to search all emails belonging to the selected conversation thread.

4. **Smart Archive Primary-Mailbox Preview (`Preview Eligible...`), Dismount Guards, No-Quota Completion & Updater Hardening:**
   - **Primary-Mailbox-Only `Preview Eligible...`:** Added **Preview Eligible...** in Archive Settings for an instant index-backed dry-run breakdown of eligible counts by folder and target Season PST without moving messages—strictly scoped to the primary mailbox (`TryGetPrimaryMailboxStoreKey`) and unconditionally excluding `.pst` archives and shared/secondary mailboxes.
   - **No-Quota Archive Completion & Responsive Status/Vacation Flows:** Added bounded no-quota readiness fallback (`IsNoQuotaFallbackReady`, `TryStartEmergencyOnly`, `_manualMetricsFallbackActive`, `TryGetFallbackConfiguredArchiveDecision`, `TrySettleNoQuotaFallbackTarget`) so **Archive Now**, **PeriodicArchive**, **Vacation Mode**, and healthy mailboxes under `SizeCeilingMB` complete and call `RecordRunToday()` without 2-second retry spin deadlocks when provider quota tags are absent (while preserving fail-closed guards when automatic daily runs lack valid quota/size). Removed UI-thread `Thread.Sleep(75)` / `DoEvents()` stalls and switched `ShowArchiveStatus()` / `VacationTick` to async/modeless notifications.
   - **Early Dismount Hook, Settle Guard & Stale Re-Verify Pruning:** Added early `BeforeStoreRemove` wiring (`HookArchiveStoreRemovalEarly()` -> `SmartArchive.NotifyUserUnmountedStore`) in `DeferredInit` before background `MaintenanceLane` startup, gated `StepSequentialSetup` pruning of unfound external `PendingReverify` / `LegacyPstAccountResolution` entries on `StartupStoreSettleComplete`, prevented manual user PST dismounts from being re-mounted or re-queued, and pruned stale unmounted external `PendingReverifyPstsV102` entries while preserving offline-routed PST verifications (`PendingOfflineReverifyPstsV122`) and Archive Root PSTs.
   - **Live Post-Drain Capacity Refresh, Transient Rollover & HTML Hardening:** Forces an immediate mailbox size/quota refresh when draining transitions to legacy PST consolidation, refreshes every 30s during consolidation and live while **Status** is open, tolerates transient mount failures before creating rollover Season PST files, and hardens **Reply with Attachment(s)** and HTML sanitization against `oledata.mso`, conditional VML comments (`<!--[if mso]-->`), and network `//` or UNC paths.
   - **Auto-Update Recovery, Office `15.0` / 32-bit MAPI Fallback & `/ETUPDATE=1` Close Safety:** Preserved `RunnerRecoveryAttempts` on intentional `UpdateRunner` exit code `14` (`HasPendingLegacyCleanupRecords()`) and cleared stale attempts in `AutoUpdateService.ClearPendingStageOnly()` (with `WaitBrieflyForPriorNameRepairWorker()` handoff coordination); added `15.0\Outlook` profile/search/catalog support alongside `16.0` and an early `Is32BitOutlookOn64BitProcess()` guard before `MAPIInitialize` in `EmailTools.PstProfileAdmin` for safe 32-bit MAPI fallback on 64-bit Windows; and extended `EmailTools.iss` `CloseOutlookCleanly()` graceful close polling to 10s (`1..40`) while skipping forced `taskkill` during silent `/ETUPDATE=1` upgrades.

5. **Task Tracker `"Waiting for Reply"` Workflow, Concurrency Safety, Cross-Store Reply Detection & Rule Precision:**
   - **Automatic `"Waiting for Reply"` & Null-Rule Sent Crash Fix:** Sent messages tracked via Search **Track as Task** default to **Waiting for Reply** with a 3-day follow-up due date, and fixed `TaskTrackerService.CreateTask` to guard `due.HasValue && rule != null && rule.ReminderDays > 0` so manually tracking Sent mail (`rule == null`) never throws `NullReferenceException`.
   - **Zero-Storm Secondary PST Handling, `_dbLock` Separation & Poison Edit Quarantine:** Stopped permanent 60-second `_hookRetryTimer` COM rescans and `NewMail` fallbacks on secondary/archive PSTs lacking default Inbox/Sent/Deleted folders (`HookResult.NotPresent` tracked via `_permanentAbsentStoreIds`); protected `_hooks` iterations with thread-safe `SafeHooksSnapshot()` / `SafeHookRefsSnapshot()` (tearing down COM outside locks); gated per-message `mail.Recipients` COM reads via `RuleNeedsRecipients` and `HydrateRecipientsForMatchedMessage`; moved `EnsureHooksForActiveWork()` outside `lock (_dbLock)` (`SaveRuleCore` / `SaveTaskCore`) with non-blocking `Monitor.TryEnter` in `HasAnyRulesOrTasksFast()`; and quarantined malformed/poison pending edits (`.pending-edits\quarantine\*.poison`, up to 3 non-SQLite retries) in `DrainPendingEdits` / `RecoverPendingEdits` instead of wedging session task edits.
   - **Cross-Store Bilingual Reply Reconciliation, Attachment Content Rules & Search:** Enhanced reply detection across stores and accounts—even for manually created tasks or stripped Conversation IDs—by pairing normalized English and Persian reply prefixes (`RE:`, `FW:`, `پاسخ:`, `عطف:`) with participant matching and localized English/Persian Sent & Deleted folder guards; extended Task Rules (`New task rule` `Body` and `Attachment` `"Name, *.ext, or text"` conditions across both indexed scans/previews and live incoming/outgoing mail) and Task Tracker's `Search tasks` box to match extracted attachment text (`attachment_fts` / `AttachmentTextExtractor`) with inline `x/y` + `📎 N` preview indicators; and fixed per-recipient address grouping (`MatchesAddressList`) and quoted single-phrase keyword unquoting (`MatchesKeywordList`).

6. **Persian/Unicode Search Parity, Mixed-DPI Scaling & SQLite Self-Healing:**
   - **Unified Zero-Allocation Text Matching:** Aligned `ConversationPersonResolver`, `MailSearchEngine`, and SQLite pushdown using low-allocation normalization (`Span<char>` / `ArrayPool<char>`), strict `<email>` domain scoping, `;`/`,` clause splitting, and Persian/Arabic zero-width (`ZWNJ`/Tatweel) word boundaries.
   - **Mixed-DPI Layout Stability:** Fixed HWND-aware mixed-DPI scaling (`100%`–`175%`) across Advanced Search and Settings dialogs so toolbars, cards, and checkboxes align cleanly without clipping.
   - **SQLite Hygiene & Performance:** Added one-time index self-healing (`search_index_repair_v122`), immutable batch collection snapshots on the async SQLite writer queue, negative FNV-1a `Rid` and MAPI recipient header verification, persistent verified-empty-body tracking, prepared SQLite command reuse, and 6-hour throttled `PRAGMA optimize`.
